# Роадмап

Розробка йде етапами. Кожен етап закінчується **робочою грою на телефоні**, навіть якщо вона ще дуже проста. Задачі виконуються по одній; після прийняття власником задача позначається `[x]`.

Кожен етап виконується в окремій гілці `milestone/m<N>-<назва>`, створеній від `main` лише після того, як гілку попереднього етапу змержено (процедура — у розділі «Git-процес» у `CLAUDE.md`).

Поле «Чого навчитесь» — підказка, на які концепції Godot звернути увагу під час етапу.

---

## M0 — Середовище і «Hello, phone»

**Мета:** переконатися, що весь ланцюжок працює: код → редактор → телефон. Це найризикованіша для новачка частина, тож робимо її першою.

- [x] Встановити інструменти за `docs/SETUP.md`
- [x] Створити Git-репозиторій, додати `.gitignore`, `CLAUDE.md`, `docs/`
- [x] Створити проєкт Godot у корені репозиторію (рендерер Compatibility) через Project Manager
- [x] Налаштувати проєкт: 720×1280, stretch `canvas_items` / `keep_width`, портретна орієнтація, емуляція дотику мишею
- [x] Тимчасова сцена: темне тло і текст «Привіт, Іскра» по центру
- [ ] Налаштувати Android-експорт і запустити сцену на телефоні через Remote Debug
- [ ] Каркас тестів: `test_runner.gd`, `test_case.gd`, один тест-заглушка; headless-команда проходить

**Готово, коли:** на телефоні відкривається тестова сцена; `godot --headless --path . -s res://tests/test_runner.gd` завершується успішно.

**Чого навчитесь:** структура проєкту Godot, вузли й сцени, Project Settings, експорт на Android.

## M1 — Герой і стрибок

**Мета:** відчути головну дію гри — стрибання з керуванням пальцем.

- [ ] `GameConfig` (Resource) і `game_config.tres` з параметрами героя, керування й плиток
- [ ] `LandingMath` + тести
- [ ] Сцена героя: коло, гравітація, автостриб
- [ ] `TouchInput`: відносний драг першого пальця + клавіатура для ПК
- [ ] Перехід через краї екрана (wrap)
- [ ] Базова сцена `Platform` (одностороння колізія) і `StaticPlatform`
- [ ] Тестова сцена з 6–8 вручну розставленими плитками; камера поки нерухома

**Готово, коли:** на телефоні можна стрибати по плитках; керування пальцем відчувається точним; дані про якість приземлення виводяться в консоль.

**Чого навчитесь:** `CharacterBody2D`, `_physics_process`, `move_and_slide`, обробка `InputEventScreenDrag`, Resource і `@export`, класи через `class_name`.

## M2 — Нескінченна вежа

**Мета:** повний ігровий цикл: старт → підйом → програш → рестарт.

- [ ] `DifficultyCurve` + тести (поки лише проміжки й швидкість прокрутки)
- [ ] `PlatformGenerator`: створення наперед і видалення під камерою (лише кам’яні плитки)
- [ ] Стартова плитка на всю ширину
- [ ] `CameraController`: слідування і автопрокрутка після першого приземлення
- [ ] `Events` (autoload) і стани забігу в `game.gd`
- [ ] Програш при виході за нижній край, рестарт по дотику
- [ ] Мінімальний HUD: висота в метрах

**Готово, коли:** можна грати нескінченно, програвати й одразу починати знову; висота рахується правильно.

**Чого навчитесь:** `Camera2D`, інстанціювання сцен (`PackedScene.instantiate()`), `queue_free`, autoload, сигнали, `RandomNumberGenerator`.

## M3 — Типи плиток

**Мета:** різноманіття, що змушує думати під час стрибка.

- [ ] Рухома плитка (відбивається від країв)
- [ ] Крихка плитка (відскок + розсипання)
- [ ] Пружина (множник стрибка + анімація стискання)
- [ ] `PlatformPicker` + тести (ваги, безпечний старт, без двох крихких поспіль)
- [ ] Повна таблиця складності з `GAME_SPEC.md` §10 у генераторі

**Готово, коли:** усі типи трапляються з потрібною частотою, а складність помітно зростає після 30 і 100 м.

**Чого навчитесь:** наслідування сцен і класів, перевизначення методів, `Tween`, `AnimatableBody2D`.

---

## M4 — Світло і комбо (серце гри)

**Мета:** реалізувати унікальну механіку і перевірити, чи вона працює.

- [ ] `ComboTracker` + тести (усі правила з `GAME_SPEC.md` §7)
- [ ] Затемнення сцени через `CanvasModulate`, герой завжди яскравий
- [ ] `PointLight2D` на героєві з радіальною текстурою
- [ ] Радіус світла залежно від комбо, плавна зміна, пульс при PERFECT
- [ ] Смуга темряви внизу екрана
- [ ] HUD: лічильник комбо; спливаючий напис «Ідеально!»
- [ ] **Тюнінг на телефоні:** 10+ забігів, підкрутити `ambient_color`, `light_base_radius`, `perfect_zone_ratio`; зафіксувати фінальні значення в `GAME_SPEC.md`

**Готово, коли:** без пояснень видно різницю між точною і недбалою грою; гра не надто темна на реальному екрані.

**Чого навчитесь:** 2D-освітлення в Godot, `CanvasModulate`, матеріали (unshaded), `GradientTexture2D`, плавні переходи.

## M5 — Меню, збереження, полірування

**Мета:** перетворити прототип на цілісний продукт.

- [ ] Головне меню з рекордом (головна сцена проєкту)
- [ ] Екран програшу зі статистикою і кнопками
- [ ] Пауза: кнопка в HUD + автопауза при згортанні застосунку
- [ ] `SaveManager`: рекорд висоти й найкраще комбо, версія формату, обробка відсутнього/пошкодженого файлу, надійний запис через тимчасовий файл + тести (ARCHITECTURE §10a)
- [ ] Перевірка на телефоні: рекорд зберігається після закриття гри й після перевстановлення APK поверх старого (без видалення)
- [ ] Safe area: HUD не перекривається вирізом камери
- [ ] Squash & stretch героя, вібрація при PERFECT (дозвіл `VIBRATE` в експорті)
- [ ] Перевірити кирилицю в стандартному шрифті; за потреби додати вільний шрифт (ліцензія OFL)
- [ ] Проста геометрична іконка застосунку і назва «Іскра»
- [ ] Debug-оверлей (FPS, комбо, швидкість прокрутки) лише в debug-збірці

**Готово, коли:** гра має всі екрани, рекорд зберігається після перезапуску, при згортанні гра стає на паузу.

**Чого навчитесь:** Control-вузли й контейнери UI, `CanvasLayer`, `ConfigFile` і `user://`, нотифікації застосунку, `OS.is_debug_build()`.

## Після MVP (не робимо зараз)

Орієнтовний порядок, який варто переглянути після плейтесту:

1. Звук і музика (найбільший приріст відчуттів за найменші зусилля).
2. Налаштування: чутливість, вібрація.
3. Здібність «спалах».
4. Тіньові плитки (видимі лише у світлі) — посилюють головну механіку.
5. Біоми з новими типами плиток.
6. Перки між біомами.
7. Щоденна вежа (seed уже підтримується) і таблиця лідерів.
8. Публікація в Google Play (AAB, Play Console, політика конфіденційності).
9. Скіни, привиди друзів, монетизація.
